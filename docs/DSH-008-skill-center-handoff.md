本需求要重构现有 `dsh-skill-manager`，但保留 DSH 已有的“扩展”外壳和左侧 `SKILL / MCP / Plugin` 导航。

## 4. 已确认的产品需求

以下内容已经在产品访谈中拍板，属于实现约束，不是建议。

### 4.1 信息架构

- 保留当前“扩展”页面外壳。
- 保留左侧 `SKILL / MCP / Plugin` 导航。
- `SKILL` 内容区包含且只包含两个 V1 子页面：
  - 项目管理（默认页）
  - 统一资源库
- Skill 市场只预留后续方向，V1 不创建可点击的假市场入口。

### 4.2 项目管理

- 默认选择当前 DSH 工作区。
- 尽量复用 DSH 已添加或最近使用的工作区。
- 允许用户手动添加本地项目目录。
- 项目级配置必须保存在项目目录中，可纳入 Git。
- 新项目默认没有任何非必需 Skill 进入模型自动候选或 Prompt。
- 即使未启用，所有 `user-invocable` Skill 仍可以通过 `/skill-name` 手动调用。
- 启停应在下一轮对话生效，不需要重启 DSH。
- 支持：
  - 按名称或完整 description 搜索
  - 全部 / 已启用 / 未启用筛选
  - 按全局标签筛选
  - 单项启停
  - 批量启停
  - 一键精简
  - 保存和应用自定义预设
- 预设应用必须先展示变化预览，并允许选择：
  - 替换当前配置
  - 合并到当前配置
- 预设只保存 Skill 身份和所选的通用来源：
  - 不锁定版本
  - 不携带项目特化内容

### 4.3 统一资源库

- 扫描并展示散落在 DSH 支持目录中的全部 Skill。
- 同名 Skill 合并为一个 Skill 身份，不重复显示成多行。
- 详情中列出该 Skill 的全部来源。
- 默认来源优先级：
  1. 项目专属
  2. DSH 用户级
  3. 其他全局来源
  4. 内置
- 当前项目可以显式选择使用哪个来源。
- 未显式选择时使用优先级中的第一个可用来源。
- 支持按名称、完整 description 和全局标签搜索/筛选。
- 全局标签属于 Skill 身份，不属于某一个来源。

### 4.4 列表与详情

- 主列表采用紧凑行和轻量分隔线，不做卡片墙。
- 每行至少展示：
  - Skill 名称
  - 完整、原始 description；不翻译、不截断
  - 全局标签
  - 项目特化状态（存在时）
  - 项目管理页的启用开关
- 点击行打开右侧详情抽屉。
- 详情抽屉展示：
  - 完整 description
  - 当前来源
  - 全部可选来源
  - 全局标签
  - 当前项目启用状态
  - 附属文件名
- “为此项目特化”属于 V1.2；V1 如展示，只能明确标记为后续能力，不能伪装可用。

### 4.5 可更新提示

- 更新状态不能单独做成一列或一个独立列表。
- 当且仅当存在真实更新数据时，在名称或“项目特化”标签后显示浅红色 `可更新` 标签。
- V1 不实现远端更新检测，不得伪造更新数据。
- 用户点击查看过某次更新后，未读提示消失；下次出现新更新时再显示。这属于后续更新能力的数据约束。

### 4.6 删除与来源回退（V1.1）

V1 不实现删除，但后续接口设计需要保留以下语义：

- 删除来源前列出受影响项目。
- 删除后如有其他来源，项目自动回退到下一个来源，并向用户说明。
- 没有其他来源时直接删除，受影响项目内该 Skill 变为不可用；不阻止删除。

### 4.7 项目特化（V1.2）

- 通用 Skill 可以在某个项目中复制并逐渐修改成项目特有 Skill。
- 切回通用来源时，已有项目特化副本保留但停止使用。
- 通用 Skill 后续更新时，二期可以通过专用 Prompt 跳转到对话，让 AI 协助合并到特化 Skill。

## 7. 已确认的 DSH 运行时事实

这些结论来自已安装 DSH 运行时和原插件代码检查，可作为实现依据，但接手者仍应在改动前复核关键接口。

- DSH 将模型自动调用与用户手动调用分开：
  - `modelInvocable`
  - `userInvocable`
- `disable-model-invocation: true` 会关闭模型自动调用，但不影响用户通过 `/skill-name` 手动调用。
- Skill 文件变更由 DSH 热加载；启停应能在下一轮生效，不要求重启 DSH。
- 当前插件为普通 Cordis Host + Client 插件：
  - Host：`plugins/skill-manager/lib/index.js`
  - Client：`plugins/skill-manager/lib/client.js`
  - 当前 Host API 版本：5
- 当前 Client 是纯 JavaScript/Cordis Client：
  - 无 JSX
  - 无 TypeScript
  - 无构建步骤
  - 使用 `React.createElement(...)`
- 当前插件已有 `/api/skill-manager` JSON 接口和旧版能力，重构时应保持新 Host 对旧 Client 的安全降级。
- Host API 如扩展，应递增版本。
- Client 改动可刷新加载；Host 改动通常需要重启本地 DSH web 进程才能验收。

## 9. 推荐实现方向

以下是 handoff 建议，不是已经落地的代码。

### 9.1 数据边界

- 全局配置建议继续使用：`~/.dsh/skill-manager.json`
  - 旧版 `globalDefaultOff` 只为兼容保留
  - 全局标签
  - 可跨项目复用的自定义预设
- 项目配置建议使用：`<projectRoot>/.dsh/skill-manager.json`
  - 已启用 Skill 身份
  - 当前来源选择
  - 最近应用的预设
  - schema/apiVersion
- 项目配置是唯一真相；文件级开关只是可重建的派生产物。

### 9.2 默认关闭

- 不迁移旧版启停状态。
- 新项目项目配置不存在时，enabled 集合为空。
- 不要在只读查询中大范围改写普通 Skill 文件。
- 只允许创建或删除带有稳定、可验证 marker 的派生开关文件。
- 对项目原生 Skill 的处理必须避免与同名 flat file / directory Skill 产生 rank 冲突。
- 删除派生产物前必须验证 marker；绝不通过路径或名称猜测删除。

### 9.3 来源选择

- UI 只操作来源 key，不直接暴露文件路径作为身份。
- 默认按已确认优先级解析。
- 如必须通过项目级复制让来源选择对 DSH 生效：
  - 在副本中写入稳定的 generated marker 和 origin source key。
  - 只允许自动覆盖仍保持 generated marker 且内容未被用户修改的副本。
  - 遇到用户文件或已修改副本应拒绝覆盖并给出明确冲突信息。
- 不要把来源选择副本标记成“项目特化”；特化代表用户已经修改内容，属于 V1.2。

### 9.4 API 兼容

- 保留现有操作，避免旧 Client 调新 Host 时崩溃。
- 新能力使用清晰的新操作名或统一状态接口。
- API version 建议从 5 升到 6。
- 旧 Client 只依赖 `>=` 能力判断时，继续确保返回字段兼容。
- 所有请求与响应必须是无损 JSON。

### 9.5 Client

- 默认进入项目管理。
- 从 DSH workspaces/session 数据选取当前项目；能力不存在时安全降级。
- 主要状态应包括：
  - activePage
  - selectedProject
  - selectedSkill
  - search
  - enableFilter
  - tagFilter
  - selected rows
  - preset preview modal
- 完整 description 允许多行自然增长，不使用 ellipsis。
- 行点击和开关点击要阻止事件串扰。
- 抽屉关闭、页面切换、项目切换后要清理无效选中项。

## 10. 安全约束

- 不覆盖用户未提交修改。
- 不删除普通 Skill、副本或用户修改内容。
- 只清理能通过内容 marker 明确识别的旧 Skill Manager 禁用开关文件。
- V1 不实现安装、删除来源或自动更新。
- 不伪造更新状态、标签、来源或项目列表。
- 项目路径必须 canonicalize，并防止路径穿越。
- 名称必须继续使用现有 `safeName` 一类校验。
- 目标为只读根时，写操作必须明确拒绝。
